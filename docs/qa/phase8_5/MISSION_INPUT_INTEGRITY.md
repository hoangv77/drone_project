# Mission and vision input integrity

QA-03, QA-07 and QA-11. Mission node wrappers now validate ROS message timestamps before renewing leases, carry source age into steady-clock deadlines, and check the actual DDS GID against one discovered writer. External stage feedback additionally requires an explicit named authority in the root namespace, correct mission and transition IDs, and a new observation sequence. Use system-time stamps for these command/mission inputs. A paused ROS clock cannot extend a lease. The CM5 passive profile keeps external stage feedback disabled.

The offline gate publishes /vision/validated_detections only when a raw detector result matches a recently rectified, calibrated image stamp in the configured optical frame, advances strictly, arrives within the image lease and comes from a graph containing only the expected apriltag writer. Configure validated_tag_ids and validated_tag_family to opt in. Results must use unique IDs and a known family. TF is queried for the body-to-optical transform at the measurement timestamp, which permits TF2's bounded interpolation and excludes a latest-transform fallback. Raw /vision/detections remains a diagnostic stream. Tag-to-camera pose still requires its own measurement-time lookup, measured tag size and verification of the TF authority.

The validation output has no mission consumer. Camera intrinsics, capture time and transform authority must be established in deployment. Discovery identity is not DDS authentication, and the Python detector gate checks graph provenance and matching calibrated stamps rather than binding each payload to an authenticated writer. Reject the validated output outside a trusted, isolated graph.
