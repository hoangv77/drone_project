# Repository audit

The requested base `hoang/cm5_integration` was at `e1974c9` and contained the PX4 interface and safety monitor. Its descendant `2f87cb9` on `codex/phase6-throw-launch` contains both mission managers and the Phase 6 SITL handoff. Phase 7 starts there. Package paths below are relative to `drone_project/`.

| Package | Executables and installed launch | ROS interfaces and dependencies |
| --- | --- | --- |
| `px4_interface_node` | `px4_interface_node` | Publishes `/drone/state` (`DroneState`). Subscribes to PX4 status, land detection, local position, odometry, GNSS, battery and failsafe flags. `/drone/execute_command` (`ExecuteCommand`) and `/drone/set_flight_mode` (`SetFlightMode`) normally share a guarded command/ACK path. Depends on `rclcpp`, `rcl_interfaces`, `builtin_interfaces` and `px4_msgs`. |
| `safety_monitor` | `safety_monitor`, `safety.launch.py` | Consumes state and publishes `/drone/safety_status` (`SafetyStatus`), with phase-aware permissions and independent freshness checks. Depends on the PX4 interface, `rclcpp`, `rcl_interfaces` and `builtin_interfaces`. |
| `state_machine_manager` | `state_machine_manager`, `throw_launch_manager`, `mission.launch.py`, `throw_sitl.launch.py` | `/drone/mission_state` (`MissionState`), `/drone/mission/stage_feedback` (`StageFeedback`), and `/drone/mission/{start,abort,reset}` (`std_srvs/Trigger`). Throw Launch consumes `NativeLaunchStatus` and uses the guarded command service. Depends on both other packages, `px4_msgs`, `std_srvs`, `rclcpp`, `rcl_interfaces` and `builtin_interfaces`. |

All three use `ament_cmake` and ROSIDL. Launch files use `launch_ros` and `ament_index_python`. ROS tests use gtest, launch testing, pytest and rclpy. C++ nodes, libraries, parameters and interfaces have portable ROS/CMake entry points. The safety monitor can run unchanged. The PX4 adapter and passive manager gain startup-only interlocks for onboard use. The Throw Launch executable builds alongside the passive manager.

`simulation/` is separate from the ROS packages. Phase 6 includes a PX4 POSIX SITL binary, Gazebo Harmonic and release plugin, x500-derived assets, MAVLink operator peer, scenario runners and a native observer that invokes SITL's `px4-param` and `px4-listener` executables. Those tools need a simulator checkout and Linux build artifacts. The native observer is unsuitable for physical telemetry as written. The simulation docs reference `/mnt/c/dev/drone_project`, a Windows Downloads STEP path and Linux-local `/tmp` overlays. Simulation tools default to `$HOME/PX4-Autopilot` or accept `PX4_ROOT`. Those paths are outside the onboard dependency chain. The onboard ROS packages contain no x86_64-specific binary dependency or WSL path.

Phase 6 staged 271 schemas from PX4 `97a3c7f01793e2b0b9e5a30425b8e88e69741f27` because the previous `FailsafeFlags` package included an extra `mode_not_supported` field. Its historical report records 129 ROS checks and successful nominal SITL runs, with a failure on unfavorable orientation. The deployed controller's firmware pin must come from that controller and its build provenance. [Phase 6 validation](../../drone_project/simulation/TEST_RESULTS.md)
